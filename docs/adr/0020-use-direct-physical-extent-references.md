# Use direct physical extent references

Immutable B+ tree pages, Blob manifests, chunks, and allocation structures refer to children using canonical physical extent references containing the file block position, allocation span, encoded length, and creation generation. The authenticated parent supplies the expected child role, and the referenced unit authenticates its physical identity and bounds. This avoids a persistent logical-ID location map and keeps random reads and independent format implementations direct, while accepting that relocation and compaction must copy affected units and rewrite their authenticated ancestor paths.
