# Compact in place with one copy-on-write publication

B+ tree compaction preflights and stages a complete relocation plan inside the existing main file, rewrites direct-reference ancestors with fresh suite-1 nonces or deterministic suite-0 checksums, and selects the result with one protected publication before truncating any unreachable suffix. It does not replace the open file through a sibling rename: keeping the predecessor intact until publication gives the ordinary old-or-new interruption proof, preserves file identity, avoids namespace-durability dependencies, and requires only the bounded workspace proven by preflight rather than a second complete database file.
