# Root each committed Blob version in a dedicated manifest extent

The Blob catalog maps each stable 128-bit Blob identifier to one direct reference for a dedicated manifest representing that snapshot's content version. Replacement creates a new manifest and chunk-index root under the same catalog key, while deletion removes the catalog entry and old snapshots retain their prior manifest. This adds one small cacheable read to opening a Blob, but keeps catalog leaves compact, gives every version one independently Protected root, and separates Blob-domain metadata from the ordered-keyspace catalog page. Suite 1 retains its Blob-derived and main-data key domains; suite 0 uses no keys.
