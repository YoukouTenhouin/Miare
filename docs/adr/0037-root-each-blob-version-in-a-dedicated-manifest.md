# Root each committed Blob version in a dedicated manifest extent

The Blob catalog maps each stable 128-bit Blob identifier to one direct reference for a dedicated Blob-keyed manifest representing that snapshot's content version. Replacement creates a new manifest and chunk-index root under the same catalog key, while deletion removes the catalog entry and old snapshots retain their prior manifest. This adds one small cacheable read to opening a Blob, but keeps catalog leaves compact, gives every version one independently authenticated root, and separates Blob-domain metadata from the main-data-encrypted catalog page.
