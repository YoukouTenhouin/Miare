# Make hard capacity limits a compile-time format profile

Hard limits are supplied through the `Limits` template policy of `Database`, with defaults of 4 KiB keys, 16 MiB values, 1 TiB Blobs, a 16 TiB database file, one million key mutations and 1,024 Blob mutations per transaction, 1 TiB of streamed Blob content and 2 TiB of file growth per transaction, and 1,024 cursors, Blob readers, and open Blob writers per transaction. The portable file records a canonical identity for all profile values, and open rejects an exact mismatch even when current contents might fit. This deliberately trades universal v1-file portability for application-tunable compile-time limits while avoiding preprocessor configuration and cross-translation-unit ODR hazards; portability is guaranteed only between implementations instantiated with the same profile.
