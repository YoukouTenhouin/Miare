# Make the inline-value cutoff part of the capacity profile

The B+ tree leaf representation stores a Value inline exactly when its logical length is at most the compile-time `maxInlineValueBytes`; `DefaultLimits` uses 1 KiB, while zero is valid and still keeps an empty Value inline. The numeric cutoff is persisted in the protected capacity profile and must match exactly on open. It may not exceed `maxValueBytes`, and the profile is rejected at compile time unless one leaf entry containing `maxKeyBytes`, `maxInlineValueBytes`, and all fixed metadata fits within the derived plaintext page capacity. Keeping this independent from the Allocation quantum lets applications tune tree fanout versus overflow reads without conflating that choice with physical allocation alignment.
