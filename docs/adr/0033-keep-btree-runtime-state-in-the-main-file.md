# Keep all B+ tree data-bearing runtime state in the main file

The v1 B+ tree backend uses copy-on-write main-file extents and alternating publication slots without a data-bearing WAL, journal, or recovery sidecar. The first barrier stabilizes new extents and the second stabilizes their root-set publication; an unsuccessful publication leaves the prior allocator and roots authoritative, with appended tail bytes abandoned and reused free ranges still free. This provides a stronger always-main-file representation than the general clean-close portability boundary, simplifying protection, transfer, and recovery while leaving future backends free to use sidecars protected according to the selected suite.
